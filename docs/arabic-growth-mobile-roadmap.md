# خارطة النمو والتطبيق

## الوضع الحالي

المنصة تحتوي على مركز قيادة ذاتية، تشغيل يومي عبر Vercel Cron، توليد محتوى عربي متعدد المنصات، فحص جودة محلي، معاينة نشر، وطبقتين منفصلتين للموافقة: اعتماد المحتوى ثم اعتماد طلب النشر. كما أصبحت قابلة للتثبيت كتطبيق ويب من خلال `manifest.webmanifest`.

## المرحلة التجارية الأولى

يبدأ المنتج بنموذج SaaS موجه لشركات التحصيل والفرق المالية. الخطة المجانية تكون مناسبة للتجربة المحدودة، والخطة المهنية تضيف التحليلات والتشغيل الآلي، بينما تضيف خطة المؤسسات الصلاحيات المتقدمة وسجل التدقيق وموصلات النشر. لا يجب تفعيل الدفع قبل تحديد مزود دفع وكيان تجاري وسياسة استرداد وخصوصية.

| المرحلة | التنفيذ | شرط الانتقال |
|---|---|---|
| اكتساب | محتوى تعليمي عربي، صفحات هبوط، معاينة منشورات | قياس الزيارات والتسجيلات دون شراء زيارات آلية |
| تفعيل | تجربة تشغيل ذاتية ومؤشرات جودة | إكمال المستخدم لأول دورة وتشغيل أول تقرير |
| تحويل | اشتراك شهري وحدود استخدام واضحة | وجود قيمة متكررة وبيانات استخدام حقيقية |
| احتفاظ | تنبيهات وتحسينات واقتراحات أسبوعية | قياس الاحتفاظ والإلغاء قبل التوسع الإعلاني |

## السوشيال

يظل النشر الخارجي منفصلاً عن إنشاء المحتوى. يجب ربط كل منصة عبر موصل رسمي، وحفظ رمز الوصول على الخادم فقط، وتسجيل معرف المنشور والاستجابة، ووضع حد للمعدل، ودعم إيقاف طارئ. المسارات الحالية تنشئ طلباً في حالة `pending` ثم تحتاج اعتماد مدير، لكنها لا ترسل أي طلب خارجي حتى تتم إضافة موصل موثق واختبار وضع المعاينة.

## التطبيق

النسخة الحالية PWA قابلة للتثبيت على Android وiPhone وتستخدم نفس واجهات API. بعد إثبات الاستخدام، يمكن بناء تطبيق React Native/Expo مستقل يعيد استخدام نفس المصادقة والعقود، مع إشعارات الدفع والتخزين المؤقت والعمل المحدود دون اتصال. لا ينبغي إنشاء تطبيق أصلي قبل معرفة بيانات الاستخدام ومسارات الهاتف الأكثر استعمالاً.

## التشغيل المستمر

الفحص اليومي يعمل عبر cron محمي بـ `CRON_SECRET`. أي دورة فاشلة تسجل سببها، وأي تشغيل مكرر يمنع بالتزامن. قبل الإنتاج يجب تطبيق ترحيل Supabase، تعريف الأسرار في بيئة النشر، تفعيل سجل مراقبة، وتجربة الاستعادة من نسخة احتياطية.
